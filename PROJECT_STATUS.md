## Completed

- Monorepo directory structure (`backend/`, `admin/`, `mobile/`, `docs/`).
- Root docs: `ARCHITECTURE.md`, `DATABASE.md`, `API.md`, `DEPLOYMENT.md`, `PRIVACY.md`, `README.md`.
- **Backend**, verified live (curl round trip: register → login → me → profile update, all 200s) and
  by test suite (`pytest`, 11/11 passing):
  - FastAPI app skeleton, pydantic-settings config, SQLAlchemy 2 async engine (SQLite dev fallback /
    Postgres via env var), Alembic wired with an async-aware `env.py`.
  - `users` + `profiles` tables, first real Alembic migration (`1787363de7f0`) generated and applied.
  - Argon2 password hashing, JWT access/refresh tokens (python-jose), `get_current_user` dependency.
  - `POST /auth/register`, `POST /auth/login`, `POST /auth/refresh`, `GET /auth/me`,
    `DELETE /auth/me` (real hard delete), `GET /profile`, `PUT /profile`.
  - `GET /api/v1/health`.
- **Admin** (Next.js 14.2.35 + TS + Tailwind), verified live in dev mode, server-rendering and
  successfully calling the backend `/health` endpoint from the dashboard page.
- `docker-compose.yml` for Postgres + backend + admin + Redis (unverified, no Docker on this machine).

## Partially Complete

- **Mobile app** — written, not compiled (no Flutter SDK):
  - Design system (`theme/app_colors.dart`, `theme/app_theme.dart`) matching spec §5 palette.
  - Core: Dio-based `ApiClient` with bearer-token injection and typed `ApiException` error mapping,
    `SecureStorage` (tokens only) vs. `AppPreferences` (SharedPreferences, onboarding flag) split.
  - `GoRouter` with Riverpod-driven redirect: splash → onboarding → login/register → home, reacting
    live to auth-state changes via a refresh-listenable notifier.
  - Splash screen, 4-page onboarding (§8), login screen, register screen — all real forms with
    validation and error states, calling the live backend endpoints above.
  - Home shell with the 5-tab bottom nav from §6 (Home / Opportunities / Prepare / Intelligence /
    Profile). Home tab shows a real greeting from `/profile` with loading/error states. Opportunities /
    Prepare / Intelligence tabs are honest "not built yet" empty states (their phases haven't landed —
    this is not the same as leaving *this* phase's own features stubbed). Profile tab shows the real
    user + a working Logout button wired to token clearing.
  - `android/` and `ios/` native project folders **not created** — these are normally generated by
    `flutter create .`, which requires the Flutter SDK; hand-rolling Gradle/Xcode project files was
    judged too failure-prone to be worth doing blind.
